Author: Aakash Kedia <a-kedia@ti.com>
Date:   Tue May 12 21:14:45 2026 +0530

    f29h85x: dthe/dma: Fix RTDMA channel start sequencing
    
    Separate DMA channel start from transfer region enable to fix
    incorrect RTDMA channel start sequencing:
    
    - Add DMA_startTxChannel() and DMA_startRxChannel() APIs to
      dma.c/dma.h with corresponding callback typedefs
    - Add startTxChannelFxn/startRxChannelFxn function pointers to
      DMA_Fxns_s struct
    - Implement RTDMA_startTxChannel() and RTDMA_startRxChannel() in
      dthe_rtdma.c/h, extracting DMA_startChannel() out of
      enableTransferRegion functions
    - Update AES, SHA, SM3, SM4 call sites to use new start channel
      APIs with correct sequence: enable region → set DMA request →
      start channel
    
    Previously DMA_startChannel() was called inside
    enableTransferRegion, causing the channel to arm before the
    hardware DMA request was enabled. This reordering ensures the
    DMA trigger is already pending when the channel starts.
    
    Fixes: TIFSMCU-5333
    
    Signed-off-by: Aakash Kedia <a-kedia@ti.com>
